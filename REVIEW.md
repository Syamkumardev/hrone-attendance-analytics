# REVIEW.md

Defects found in the starter `app/main.py`. "Fixed" refers to the current `app/main.py`.

| # | Where (function / line) | What is wrong | How you'd notice it (test, input, or symptom) | How you fixed it |
|---|---|---|---|---|
| 1 | `compute_late_minutes` | Builds the shift start from the punch-in's *own* date and time zone (naive server-local time), not from the IST attendance date. | On a UTC server a 10:05 IST punch-in (04:35 naive) is compared with 09:30, giving a negative number, so `late_minutes` is always 0. | Shift start is built for the record's IST `date` with `tzinfo=IST` (`shift_start_at`); all instants are UTC-aware. |
| 2 | `compute_late_minutes` | Floors to minutes *before* the grace check (`int(s/60) > 10`). | Shift 09:30, punch 09:40:01: 10 minutes, not `> 10`, so returns 0. R2 says 10. | Compare whole seconds (`seconds > 600`), then floor to minutes. |
| 3 | `compute_late_minutes` | Overnight shifts are not handled: a punch-in after midnight is measured against a start time on the wrong day. | Shift 22:00-06:00, punch 00:30 IST: start becomes 22:00 *that* day, so late = 0 instead of 150. | `attendance_date` assigns the record to the previous day (R1); lateness is measured from that day's shift start. |
| 4 | `compute_work_hours` | `round()` on a float: banker's rounding on binary values; no truncation to whole seconds. | 16218 s is exactly 4.505 h; `round(4.505, 2)` returns 4.5, but R4 (half-up) requires 4.51. | Exact `Decimal` arithmetic with `ROUND_HALF_UP` (`round_half_up`). Inputs are truncated to seconds at the boundary. |
| 5 | `compute_overtime` | No 30-minute minimum (R3): `max(0, minutes)`. | Shift ends 18:30, punch-out 18:40: returns 10, should be 0. | Count overtime only when `minutes >= 30`. |
| 6 | `compute_overtime` | Builds an *aware* shift end (`tzinfo=IST`) but the starter's other code produces *naive* datetimes, so reusing the helper for punch-out (a TODO in the starter) cannot work. | Calling it with the naive datetimes the starter creates raises `TypeError: can't subtract offset-naive and offset-aware datetimes`, which would be a 500. | Everything is UTC-aware (`tz_aware=True` on the client, `as_utc` at the edges). |
| 7 | `compute_overtime` | Overnight shift end is not moved to the next day. | Shift 22:00-06:00, punch-out 06:40 next day: end is computed as 06:00 on the *start* day, giving about 24 h of overtime. | `shift_end_at` adds one day when `shift_end <= shift_start`. |
| 8 | `EmployeeIn` | No validation at all. | `emp_code:"x"`, `shift_start:"25:99"`, `joined_on:"2026-02-30"`, or `shift_start == shift_end` are accepted. The bad shift string later crashes `compute_late_minutes` with a 500. | Patterns, length limits, a strict date check and a `shift_start != shift_end` validator, giving 422. |
| 9 | `PunchInIn` | `status: str` accepts anything, including `ABSENT`/`LEAVE`/garbage. `punched_at: Optional[int]` accepts seconds, numeric strings and `True`, and `if body.punched_at` treats 0 as "missing". | `{"status":"ABSENT"}` is stored. `punched_at: 1783312500` (seconds) gives a 1970 date. | `PresenceStatus` literal and strict `EpochMillis` (int only, 1e11 to 4.1e12), giving 422. |
| 10 | Module top (`MongoClient`) | No `tz_aware`, so the driver returns naive datetimes. No server-selection timeout (30 s default). | Naive/aware arithmetic errors. `/health` and every request hang for 30 s when MongoDB is down. | `MongoClient(..., tz_aware=True, serverSelectionTimeoutMS=5000)`. |
| 11 | Whole app | No indexes and no unique constraints. | 100k-record collection scans on every list/analytics call. Races (items 13, 16) are not preventable. | `ensure_indexes()` at startup (idempotent), including two unique indexes. |
| 12 | `/health` | Always returns `ok` without touching MongoDB. | Stop MongoDB: still 200. Contract requires 503. | Pings MongoDB and returns 503 on failure. A global handler also maps driver errors to 503 instead of 500. |
| 13 | `create_employee` | Check-then-insert race (`find_one` then `insert_one`) with no unique index. | 10 parallel POSTs with the same `emp_code` produce several 201s and duplicate documents. | Unique index on `emp_code`; catch `DuplicateKeyError` and return 409. |
| 14 | `create_employee` / `punch_in` | `datetime.now()` is naive server-local time and is stored as if it were UTC. Responses contain datetimes (ISO strings), not epoch ms. | `created_at` is off by the server's UTC offset. Clients get `"2026-07-06T10:05:00"`. | `now_utc()`; every instant is serialised with `to_ms` (`serialize_*`). |
| 15 | `list_employees` | `skip = page * page_size` skips the first page. `total` counts the whole collection, ignoring the department filter. No sort. `page`/`page_size` unvalidated. | `?page=1` returns what should be page 2. `?department=Ops` reports every employee in `total`. `page_size=0` or `page=0` gives a driver error (500). | `skip = (page-1)*page_size`; `count_documents(query)`; `sort("emp_code")`; `Query(ge=1, le=100)`. |
| 16 | `punch_in` | Check-then-insert race. | 12 parallel identical punch-ins produce several 201s and duplicate records for one day. | Unique `(emp_code, date)` index; exactly one insert wins and the rest get `DuplicateKeyError`, returned as 409. |
| 17 | `punch_in` | Unknown employee: `emp` is `None`, so `emp["shift_start"]` raises `TypeError`. | `{"emp_code":"NOPE"}` returns 500; the contract says 404. | `get_employee_or_404`. |
| 18 | `punch_in` | `datetime.fromtimestamp(ms/1000)` uses server-local naive time and a float. No truncation to seconds. The date is not the IST date (R1) and ignores overnight shifts. | Server in UTC: a 01:00 IST punch-in (19:30 UTC the day before) gets the previous day's date. Sub-second parts are kept instead of truncated. | `utc_from_ms` (integer division to whole seconds, UTC) and `attendance_date` (IST date plus the overnight rule). |
| 19 | `punch_in` | Returns `id` (the stringified ObjectId). | Response contains `id`. The contract says `_id` never appears. | `serialize_attendance` uses an explicit field list. |
| 20 | `list_attendance` | `list(find(q))` loads every match into memory, sorts in Python and slices. `total=len(docs)`. | 100k documents are loaded per request: seconds of latency and high memory. | Server-side `sort/skip/limit` with a hinted index; `count_documents` (or `estimated_document_count` when unfiltered). |
| 21 | `list_attendance` | Sort is `date` desc only, with no `emp_code` tie-break (the sort is stable on natural order). | Two employees on the same date come back in insertion order, not `emp_code` order. | Sort `[("date",-1),("emp_code",1)]`, matching the `(date desc, emp_code)` index. |
| 22 | `list_attendance` | Filters are unvalidated, and `page`/`page_size` are not bounded. Legacy records are returned as stored (no `history`/`half_day` defaults), datetimes as ISO strings, plus the `id` leak. | `date_from > date_to` returns an empty list instead of 422. `status=NOPE` is accepted. `page=0` slices from the end. | Strict `YYYY-MM-DD` parsing, a `Status` literal, `date_from <= date_to` check, `Query` bounds, and `serialize_attendance` applies the documented defaults. |

## Examined and judged not a defect

- `load_dotenv()` is called with the default `override=False`, so real environment variables already take priority over `.env` (required by the contract).
- Endpoints are plain `def`, so FastAPI runs them in its threadpool; blocking PyMongo calls do not block the event loop.
- The `IST` constant (`UTC+05:30`) is correct, and `doc.pop("_id")` after `insert_one` is correct (the driver adds `_id` to the dict).
- A default of `mongodb://localhost:27017` when `MONGO_URI` is unset is a local-development convenience only: the environment always wins, so it never overrides injected settings. I kept it deliberately; it can be removed if a hard failure is preferred.
